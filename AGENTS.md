# cesium-helpers

Lerna monorepo of small CesiumJS helpers under `packages/` (published as `@geoblocks/*`), with demos in `demos/`.
The code is plain ES modules in JavaScript, typed with JSDoc and checked by `tsc`.

## Use Cesium as much as possible

Before writing any math, helper, constant, shader function or camera/scene logic, look for it in Cesium and use it.
Do not hand-roll what Cesium provides. Search the installed packages (`node_modules/@cesium/core/Source`,
`node_modules/@cesium/engine/Source`, including `Shaders/Builtin`), or the CesiumGS/cesium repository and the
CesiumJS API reference. Confirm the symbol is exported from `@cesium/core` or `@cesium/engine`, and read its
signature, before using it.

- Math: `CesiumMath` (`toRadians`, `clamp`, `lerp`, `mod`, `negativePiToPi`, `zeroToTwoPi`, `equalsEpsilon`,
  `EPSILON*`, `PI`, `TWO_PI`, `PI_OVER_*`), and the `Cartesian2/3`, `Matrix3/4`, `Quaternion` statics. Pass a result
  object and reuse scratch variables.
- Frames and geometry: `FixedFrameTransforms`/`Transforms`, `HeadingPitchRoll`, `Ellipsoid` methods
  (`geodeticSurfaceNormal`, `scaleToGeodeticSurface`), `EllipsoidGeodesic`, `IntersectionTests`, `Ray`, `Plane`,
  `BoundingSphere`, `Axis`.
- Animation and data: `EasingFunction`, `CatmullRomSpline` and the other splines, `Resource` for fetching, `Event`,
  `Color`, `defined`, `Frozen`, `destroyObject`.
- Camera and scene: `Camera` methods, `ScreenSpaceCameraController` options (such as `enableInputs`),
  `ScreenSpaceEventHandler`, `scene.pickPosition`, `globe.getHeight`, `sampleTerrain*`.
- GLSL: the `czm_*` builtins, constants and automatic uniforms (`czm_luminance`, `czm_saturation`, `czm_RGBToHSL`,
  `czm_pi`, `czm_viewport`, `czm_inverseProjection`, `czm_ray`, ...). Check
  `packages/engine/Source/Shaders/Builtin` before writing a shader helper.

Keep custom code only when Cesium has no public equivalent or its behavior differs on purpose, and say why in a short
comment. Known cases: smoothstep, damping and Gaussian smoothing, the quantized-mesh terrain sampler
(`cesium-path-flyover/terrain.js`), the hand-built orthographic ENU placement in `cesium-iso` (Cesium's `setView` reads
the depth buffer), `requestAnimationFrame` loops that must run under `requestRenderMode`, and anything marked `@private`
or `@internal` in Cesium. Do not use private or internal Cesium APIs.

## Write ES2025

Use the language's newer built-ins over the older idioms:

- Iterator helpers: `map.values().filter(...).toArray()`, not `[...map.values()].filter(...)`. Spread or
  `Array.from` only when an array is needed as such (to sort, reverse or index it).
- Set methods: `union`, `intersection`, `difference`, `symmetricDifference`, `isSubsetOf`, `isSupersetOf`,
  `isDisjointFrom`, not `filter` with `has`.
- JSON modules: `import data from './data.json' with {type: 'json'}`, not `JSON.parse(readFileSync(...))`, unless the
  file's name is known only at run time or a test needs a fresh copy to change.
- `Promise.try`, `RegExp.escape` and `Float16Array` where they fit.

## Cesium behavior to design around

- Moving a `PolylineCollection` by its `modelMatrix` rebuilds its vertices every frame: `PolylineCollection.update` sets `_createVertexArray`
  when `modelMatrix` differs from the one the vertices were last built with (`Source/Scene/PolylineCollection.js`). Measured with 1400
  polylines, two collections of 700 moved by one translation each frame: about 4 ms a frame (a desktop GPU, 9.9 ms against 6.0 with the matrix
  frozen), the drawing itself 2 ms more. `BillboardCollection` and `PointPrimitiveCollection` move by their matrix for nothing measurable. For
  many short marks that move together (rain streaks, flakes, sparks), use billboards (an upright streak is a billboard with an `alignedAxis`
  and a thin image) or points; keep polylines for what is built once.

## Layout and commands

- `npm test` runs `node --test "packages/**/*.test.js"`. `npm run typecheck` runs `tsc`. `npm run build-demos` runs
  `vite build`; `npm run dev` serves the demos from `demos/`.
- Shaders: edit `packages/*/shaders/*.glsl`. The `.js` next to each is generated by `npm run build-shaders`
  (also run on `prepare` and by the vite dev server) and is gitignored.
- Packages import from `@cesium/core` and `@cesium/engine`, declared as peer dependencies, never from the `cesium`
  monolith. Keep a dependency-free package (such as `cesium-input`) free of Cesium.
- The demos load Cesium from the CDN, and `demos/cesium-shim.js` re-exports `window.Cesium`. When a package imports a
  new Cesium symbol, add it to the shim (alphabetical) or the demo build fails. Run `npm run build-demos` to check.
- A package with a `files` list in its `package.json` must list every file its listed files import
  (`packages/package-files.test.js` checks it).

## Test pages

- `demos/cesium-overlay.html` tests and benchmarks cesium-overlay's lines: a grid of boxes, nothing to load but Cesium, lines
  of each kind (`occlude: 'depth'`, a caller's test, a fill, strokes). In the browser, `await bench.measure({view})` (`view`
  one of `bench.views`) gives the renders' times, when the hidden parts first change and settle after a stop, the depth reads
  and long tasks; `?continuous` renders every frame. Run it before and after a change to the lines and compare.

## Before finishing a change

Run `npm test`, `npm run typecheck` and `npm run build-demos`. For a shader change, load the demo (`npm run dev`) and
check the browser console for GLSL compile errors.
